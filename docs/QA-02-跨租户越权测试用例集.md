| 属性 | 值 |
|------|-----|
| 文档版本 | V1.0 |

| 性质 | 安全门禁用例，全部通过方可发布 |

---

## 1. 测试目标

确保在多租户 SaaS 环境下：
1. 租户 A 的任何用户无法读取、写入、删除租户 B 的任何数据
2. 关闭功能后 API 不可用且无残留逻辑
3. 配额耗尽时行为正确

---

## 2. 测试数据准备

```rust
// server/tests/fixtures/tenant_fixture.rs
pub struct TenantFixture {
    pub tenant_a: TenantContext,
    pub tenant_b: TenantContext,
}

pub struct TenantContext {
    pub tenant_id: Uuid,
    pub admin_token: String,
    pub normal_user_token: String,
    pub org_id: Uuid,
    pub member_ids: Vec<Uuid>,
    pub meeting_ids: Vec<Uuid>,
    pub course_ids: Vec<Uuid>,
}

pub async fn setup_two_tenants(ctx: &TestContext) -> TenantFixture {
    // 创建租户 A：含 1 个组织、3 个党员、2 个会议、1 门课程
    let tenant_a = create_tenant_with_data(ctx, "TenantA", "org_a").await;
    // 创建租户 B：同上结构但不同 ID
    let tenant_b = create_tenant_with_data(ctx, "TenantB", "org_b").await;
    TenantFixture { tenant_a, tenant_b }
}
```

## 3. 测试用例矩阵

### 3.1 水平越权 — 读取（IDOR）

| 编号 | 场景 | 操作 | 预期结果 | HTTP 状态码 |
|------|------|------|----------|------------|
| CT-R001 | 党员详情 | 用 Token_A 访问 `/party/members/{member_b_id}` | 403 Forbidden | 40301 |
| CT-R002 | 会议详情 | 用 Token_B 访问 `/party/meetings/{meeting_a_id}` | 403 Forbidden | 40301 |
| CT-R003 | 课程详情 | 用 Token_A 访问 `/learning/courses/{course_b_id}` | 404 Not Found | 40400 |
| CT-R004 | 组织树 | 用 Token_B 获取组织树 → 确认不包含 Tenant_A 的组织节点 | 仅返回 B 数据 | 200 |
| CT-R005 | 党员列表搜索 | 用 Token_A 搜索 `real_name=TenantB党员姓名` | 返回空列表 | 200 |
| CT-R006 | 网格事件详情 | 用 Token_A 访问 `/grid/events/{event_b_id}` | 403 | 40301 |
| CT-R007 | 审批任务 | 用 Token_A 获取待办 → 不包含 Tenant_B 的任务 | 仅返回 A 数据 | 200 |

### 3.2 水平越权 — 写入

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|----------|
| CT-W001 | 更新他人党员档案 | PUT `/party/members/{member_b_id}` with Token_A | 40301 |
| CT-W002 | 在他人组织创建党员 | POST `/party/members` body 含 `org_id=org_b` with Token_A | 40301 或自动纠正为 org_a |
| CT-W003 | 提交他人会议签到 | POST `/checkin` biz_id=meeting_b with Token_A | 40301 |
| CT-W004 | 审批他人工作流 | POST `/workflows/instances/{instance_b}/signals` with Token_A | 40300 |
| CT-W005 | 创建网格事件到他人网格 | POST `/grid/events` grid_id=grid_b with Token_A | 40301 |

### 3.3 水平越权 — 删除

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|----------|
| CT-D001 | 删除他人党员 | DELETE `/party/members/{member_b_id}` with Token_A | 40301 + 数据未被删除 |
| CT-D002 | 删除他人会议 | DELETE `/party/meetings/{meeting_b_id}` with Token_A | 40301 |

### 3.4 导出与文件访问

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|----------|
| CT-E001 | Excel 导出仅含本租户 | GET `/party/members/export` with Token_A | 文件中无 Tenant_B 数据行 |
| CT-E002 | 文件路径穿越 | GET `/files/{tenant_b}/{module}/{date}/{file}` with Token_A | 40301 |
| CT-E003 | 上传到他人路径 | POST `/files/upload` 尝试指定 tenant_id=b | 服务端强制使用 Token 中 tenant_id |

### 3.5 开放 API 租户隔离

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|----------|
| CT-O001 | OpenAPI 只能访问绑定租户 | 用 AppId_A (bound to tenant_a) 调用 `/open/v1/grid/events/{event_b_id}` | 40301 |
| CT-O002 | OpenAPI 创建事件归属正确 | 用 AppId_A 创建事件 | 事件的 tenant_id 自动为 tenant_a |
| CT-O003 | Webhook 不泄露其他租户 | 注册 Webhook 后触发 Tenant_B 的事件变更 | Tenant_A 的 Webhook 不收到通知 |

## 4. 功能开关测试

| 编号 | 场景 | 操作 | 预期结果 |
|------|------|------|----------|
| FS-001 | OPS 关闭人脸模块 | 设置 tenant_a 功能开关 face_verify=false | 人脸相关 API 返回 403；前端菜单隐藏 |
| FS-002 | OPS 关闭 AI 模块 | 设置 ai_enabled=false | `/ai/execute` 返回 40302 |
| FS-003 | 冻结租户 | 将 tenant_b 状态设为 frozen | 所有 API 对 tenant_b 返回 40300；已登录用户被踢出 |
| FS-004 | 关闭租户后数据不可见 | tenant_b status=closed | 任何请求均拒绝；数据保留但不可访问 |
| FS-005 | 重新激活租户 | frozen → active | 数据恢复可访问 |

## 7. CI 自动化集成

所有上述用例纳入 Rust integration tests：

```bash
# CI Pipeline 中运行安全门禁
cargo test --test cross_tenant_security --test feature_flags --test quota_limits --test permission_granularity
```

失败策略：任何一个用例失败 → 阻止合并和部署。
