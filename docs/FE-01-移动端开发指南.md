| 属性 | 值 |
| --- | --- |
| 文档版本 | V1.2 |
| UI 框架 | RedHub Mx UI（`mobile/uni_modules/mx-ui`） |
| 基座来源 | Cool Unix MIT 二次开发，公共命名统一为 `mx-*` / `Mx*` |
| 跨端引擎 | uni-app x + UTS |
| 上游依赖 | TA-01、PM-03、FE-03 |

## 1. 环境与运行

```bash
cd mobile
pnpm install
```

使用 HBuilderX 打开 `mobile/` 目录。首次导入可执行：

```bash
/Applications/HBuilderX.app/Contents/MacOS/cli project open --path "$PWD/mobile"
```

编译验证：

```bash
/Applications/HBuilderX.app/Contents/MacOS/cli launch web --project "$PWD/mobile" --compile true --ui false
/Applications/HBuilderX.app/Contents/MacOS/cli launch mp-weixin --project "$PWD/mobile" --compile true --ui false
```

Node 包缓存写入 `/Volumes/fushilu/.caches/redhub/pnpm-store`；项目构建输出通过 `mobile/unpackage` 链接到外部磁盘。

### 1.1 Web 预览上下文

Mx UI 使用 `@/.mx/ctx` 读取页面、主题和 Tailwind 颜色。由于上游 Cool Unix 的上下文插件只识别 `.cool/ctx`，Mx 的 `build/unix.ts` 额外注册了 `redhub-mx-context` 插件，在 Web/H5 编译时注入 `pages.json`、`theme.json`、`manifest.json` 和当前色板。

如果页面出现空白，优先检查浏览器控制台是否有 `ctx.pages is not iterable`：

1. 确认使用项目自己的 `mobile/build/unix.ts`，不要绕过 Vite 配置直接启动普通 Vite。
2. 重启 HBuilderX Web 运行，清除浏览器对 `localhost:9900` 的旧模块缓存。
3. 确认 `mobile/unpackage` 仍指向 `/Volumes/fushilu/.caches/redhub/build-output/mobile`，不要直接修改生成目录。

## 2. 目录结构

```text
mobile/
├── .mx/                       # Mx 运行时：请求、路由、状态、主题、工具
├── .cool/                     # HBuilderX 兼容重导出，业务代码禁止引用
├── build/unix.ts              # 上游构建插件适配层，导出 mx()
├── components/                # 全局业务组件
├── config/                    # 环境、代理与网关地址
├── pages/                     # 页面，必须在 pages.json 注册
├── plugins/                   # 应用级插件
├── uni_modules/mx-ui/         # 通用 UI 组件库
├── tailwind.config.ts         # 设计令牌
├── theme.json                 # 系统亮暗主题
└── manifest.json              # uni-app x 应用配置
```

边界规则：

- `.mx` 只放跨页面基础能力，不写党务业务。
- `uni_modules/mx-ui` 只放通用组件和交互能力，不请求 RedHub 业务 API。
- 页面只组合 `mx-ui` 与业务组件；重复出现两次以上的视觉结构应下沉为组件。

## 3. 运行时核心概念

### 3.1 请求

`request` 统一拼接网关、注入 Token 和语言，并在响应码为 `1000` 时返回 `data`。

```ts
import { request } from "@/.mx";

const members = await request({
	url: "/app/party/member/page",
	method: "GET",
	data: {
		page: 1,
		limit: 20,
		orgId: "110000"
	}
});
```

规则：

- 页面内不要手工读取 Token 或拼接 `config.baseUrl`。
- 错误对象按 `Response` 处理，展示 `message`。
- 新接口必须先补充 TA-03，再在移动端调用。

### 3.2 状态

uni-app x 不使用 Pinia。全局状态由 `.mx/store` 的轻量单例管理。

```ts
import { useStore, userInfo } from "@/.mx";

const { user } = useStore();

await user.get();
if (user.isNull()) {
	router.login();
}
```

登录成功后保存凭证并回到来源页：

```ts
user.setToken(parse<Token>(res)!);
await user.get();
router.nextLogin();
```

### 3.3 路由

```ts
import { router } from "@/.mx";

router.to("/pages/demo/design/system");

router.push({
	path: "/pages/party/member-detail",
	query: { id: memberId },
	mode: "navigateTo"
});

router.back();
```

TabBar 页面会被自动转换为 `switchTab`。需要登录的页面在 `pages.json` 中配置 `meta.isAuth: true`。

### 3.4 UI 服务

弹窗、吐司、加载等通过 `useUi()` 调用：

```ts
import { useUi } from "@/uni_modules/mx-ui";

const ui = useUi();

ui.showToast({ message: "已提交" });
ui.showLoading("提交中");
ui.hideLoading();
```

## 4. Mx UI 使用规范

优先使用 easycom 组件，不需要手动 import：

| 场景 | 推荐组件 |
| --- | --- |
| 内容分组 | `mx-section` + `mx-card` |
| 指标展示 | `mx-metric`、`mx-rolling-number` |
| 列表页 | `mx-list-view`、`mx-list-item`、`mx-empty` |
| 表单 | `mx-form`、`mx-input`、`mx-select`、`mx-upload` |
| 反馈 | `mx-toast`、`mx-confirm`、`mx-popup`、`mx-action-sheet` |
| 数据展示 | `mx-banner`、`mx-timeline`、`mx-progress`、`mx-skeleton` |
| 特色能力 | `mx-qrcode`、`mx-sign`、`mx-slide-verify` |

组件样式穿透统一使用 `pt.className`：

```html
<mx-card title="组织活动" :pt="{ className: 'mb-4' }"></mx-card>
```

设计令牌、容器组件和质量门槛见 [FE-03](./FE-03-Mx-UI设计系统.md)。

## 5. 页面模板

```uvue
<template>
	<mx-page>
		<view class="p-3">
			<mx-section title="党员详情" description="组织内可见字段由后端鉴权返回">
				<mx-card>
					<mx-text :size="16">{{ member.realName }}</mx-text>
					<mx-text :size="13" color="info">{{ member.orgName }}</mx-text>
				</mx-card>
			</mx-section>
		</view>
	</mx-page>
</template>

<script setup lang="ts">
	import { onMounted, ref } from "vue";
	import { request } from "@/.mx";

	type PartyMember = {
		realName: string;
		orgName: string;
	};

	const props = defineProps({
		id: {
			type: String,
			default: ""
		}
	});
	const member = ref<PartyMember>({
		realName: "",
		orgName: ""
	});

	onMounted(async () => {
		member.value = (await request({
			url: "/app/party/member/info",
			method: "GET",
			data: { id: props.id }
		})) as PartyMember;
	});
</script>
```

UTS 规则：

- 不依赖类型隐式转换；条件判断必须是布尔值或显式比较。
- 可空值使用 `T | null`，访问前判空或使用安全调用。
- 对象类型优先使用 `type`，避免把 TS 的 interface 语义直接迁移到 UTS。
- 平台差异必须用 `#ifdef APP`、`#ifdef MP`、`#ifdef H5` 明确包裹。

## 6. 登录与多租户

当前骨架已接入手机验证码和小程序登录入口，后端约定：

| 场景 | 接口 |
| --- | --- |
| 发送短信验证码 | `POST /app/user/login/captcha` |
| 手机号登录 | `POST /app/user/login/phone` |
| 微信小程序登录 | `POST /app/user/login/mini` |
| 刷新凭证 | `POST /app/user/login/refreshToken` |
| 当前用户 | `GET /app/user/info/person` |

单位码/租户上下文不得保存在页面局部状态；登录成功后应随用户会话持久化，并由 Rust 后端在每个请求中校验归属关系。

## 7. 质量检查

提交前至少执行：

1. 微信小程序全量编译。
2. H5 编译和关键路径人工走查。
3. 亮色、暗色双主题检查。
4. 新增页面在 iPhone SE 尺寸下的布局检查。
5. 可点击区域不小于 44×44px。
6. 检查无 `cl-*`、`cool-*`、`Cl*`、`Cool*` 业务命名残留。

Web 预览启动成功后默认地址为 `http://localhost:9900/`；设计系统验收页为 `http://localhost:9900/#/pages/demo/design/system`。

所有新增通用组件必须更新 FE-03、`index.d.ts` 和设计系统演示页。
