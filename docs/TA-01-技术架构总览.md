## 2. 技术栈决策记录（ADR）

| 编号 | 决策 | 理由 | 备选方案 |
|------|------|------|----------|
| ADR-001 | 后端使用全栈 Rust | 单二进制交付；工作流引擎类型安全；AI Gateway 低延迟；内存安全降低等保风险 | Go / Java Spring Boot |
| ADR-002 | Web 框架选 Axum | tokio 生态成熟；中间件链清晰；社区活跃度高 | Actix-web / Poem |
| ADR-003 | ORM 选 SeaORM | 提供实体关系映射；支持迁移；与 Axum 配合良好 | SQLx（纯 SQL）/ Diesel |
| ADR-004 | 移动端基于 Cool Unix 二开 | 开源 MIT 免费商用；与 cool-admin 同生态；内置脚手架完整 | unibest / 原生开发 |
| ADR-005 | WASM 沙箱用 wasmtime | Bytecode Alliance 维护；性能优秀；安全模型完善 | Wasmer / QuickJS |
| ADR-006 | 工作流不用传统 BPMN | 事件溯源 + 声明式规则 + Durable Execution 更灵活且 AI 友好 | Camunda / Flowable |
| ADR-007 | 管理端 UI 选 shadcn-vue | 无头组件代码完全可控；Tailwind CSS 深度集成；AI 辅助编码效果最佳 | Naive UI / Element Plus |

## 3. Rust Crate 结构与依赖规则

### 3.1 Cargo Workspace

```toml
[workspace]
resolver = "2"
members = [
    "crates/common",
    "crates/platform",
    "crates/party",
    "crates/learning",
    "crates/service",
    "crates/grid",
    "crates/workflow",
    "crates/ai-gateway",
    "crates/checkin",
    "crates/payment",
    "server",
]
```

### 3.2 Crate 依赖关系

```text
server (主入口)
  ├── party ────────► common, platform, workflow, checkin
  ├── learning ─────► common, platform, workflow, ai-gateway
  ├── service ──────► common, platform, workflow, checkin, payment
  ├── grid ─────────► common, platform, workflow
  ├── platform ─────► common
  ├── workflow ─────► common
  ├── ai-gateway ───► common
  ├── checkin ──────► common
  ├── payment ──────► common
  └── common         （无业务依赖，仅工具和类型定义）
```

**强制规则：**

1. 业务域 crate（party / learning / service / grid）之间禁止直接依赖。
2. 共享内核 crate（workflow / ai-gateway / checkin / payment）禁止依赖任何业务域。
3. 所有 crate 必须依赖 `common`，但 `common` 不依赖任何其他 crate。
4. 跨域通信通过事件总线或平台底座提供的接口进行。

## 4. 核心设计模式

### 4.1 Repository Trait Pattern

每个业务域定义自己的数据访问 trait，便于单元测试时 mock：

```rust
// crates/party/src/repository.rs
#[async_trait::async_trait]
pub trait PartyMemberRepo: Send + Sync {
    async fn find_by_id(&self, tenant_id: Uuid, id: Uuid) -> Result<Option<PartyMember>>;
    async fn find_by_org(&self, tenant_id: Uuid, org_id: Uuid, page: PageReq) -> Result<Page<PartyMember>>;
    async fn create(&self, member: NewPartyMember) -> Result<PartyMember>;
    async fn update(&self, member: PartyMember) -> Result<PartyMember>;
    async fn soft_delete(&self, tenant_id: Uuid, id: Uuid) -> Result<()>;
}
```

生产实现使用 SeaORM + PostgreSQL；测试实现使用 Mock。

### 4.2 Middleware Pipeline

```rust
pub fn middleware_stack(app: Router) -> Router {
    app
        .layer(CorsLayer::permissive())          // 1. CORS
        .layer(AuthLayer)                         // 2. JWT 认证
        .layer(TenantContextLayer)                // 3. 租户上下文注入
        .layer(RbacLayer)                         // 4. RBAC 权限校验
        .layer(AuditLogLayer)                     // 5. 审计日志
        .layer(RateLimitLayer)                    // 6. API 限流
}
```

### 4.3 Event Bus

领域事件通过异步广播解耦：

```rust
pub enum DomainEvent {
    MemberCreated { tenant_id: Uuid, member_id: Uuid },
    MeetingScheduled { tenant_id: Uuid, meeting_id: Uuid },
    GridEventSubmitted { tenant_id: Uuid, event_id: Uuid },
    LearningCompleted { tenant_id: Uuid, user_id: Uuid },
}

pub trait EventBus: Send + Sync {
    async fn publish(&self, event: DomainEvent);
    fn subscribe(&self, handler: Box<dyn EventHandler>);
}

// 实现：Redis Pub/Sub（多实例场景）
// 或 tokio::sync::broadcast（单实例简化模式）
```

### 4.4 Rule Engine（共享 DSL 求值器）

条件表达式求值引擎被工作流、预警、自动化任务共用。使用安全的表达式求值库，禁止任意代码执行。

## 5. 数据层设计

### 5.1 PostgreSQL

- 主从分离：写走主库，读走只读副本（可选，初期单实例）
- 连接池：SQLx 内置连接池，最大连接数按实例数 × 10 配置
- 迁移：SeaORM migration，版本化管理

### 5.2 Redis

| 用途 | Key 格式 | TTL |
|------|----------|-----|
| 会话缓存 | `session:{token_hash}` | 与 JWT 过期一致 |
| 权限缓存 | `perm:{tenant_id}:{user_id}` | 300s |
| 限流计数 | `rate:{tenant_id}:{endpoint}` | 窗口期 |
| 任务队列 | apalis 默认 key | N/A |
| SSE 推送通道 | `sse:{tenant_id}:{user_id}` | 连接生命周期 |

### 5.3 对象存储

- Mode-S：MinIO 自托管或阿里云 OSS
- Mode-D：客户环境 MinIO 或兼容 S3 协议的存储
- 路径规范：`/{tenant_id}/{module}/{yyyy-MM-dd}/{uuid}.{ext}`

## 6. 部署形态

### 6.1 Mode-S 标准版多租户

Docker Compose 或 Kubernetes 部署，Helm Chart 管理。

## 7. 安全架构要点

详细实现方案见 TA-06：

1. **认证**：JWT（RS256 签名），Access Token 30min + Refresh Token 7d
2. **租户隔离**：ORM 层自动注入 tenant_id 条件；禁止手动拼接查询绕过
3. **密码存储**：Argon2id 哈希
4. **API 安全**：HTTPS 强制；敏感操作二次确认；开放 API 签名验证
5. **数据加密**：传输 TLS 1.3；存储敏感字段 AES-256-GCM 加密

## 8. 可观测性

详细方案见 OPS-02：

1. **日志**：tracing 结构化 JSON 日志输出到 stdout
2. **指标**：Prometheus `/metrics` 端点暴露自定义业务指标
3. **追踪**：OpenTelemetry 标准，request_id 全链路透传
4. **告警**：错误率 > 1%、P99 延迟 > 2s、任务积压 > 100 时触发
